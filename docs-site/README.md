# docs-site

The VitePress site behind <https://docs.spacingmind.com>. It reads the pages from `../public-docs/`; the site itself (theme, `llms.txt`, `sitemap.xml`, SEO tags, the `_headers` file) lives here.

```sh
cd docs-site
npm ci
npm test                          # node --test scripts/*.test.mjs
npm run build                     # -> .vitepress/dist, with _headers (strict CSP, nosniff, ...)
node scripts/check-dist.mjs       # every page has its content, the CSP lists every inline script's hash
npm run dev                       # VitePress dev server
```

## Hosting: a Cloudflare Worker, deployed when a release is cut

The site is the static-assets-only Worker `smind-docs` (`wrangler.docs.jsonc`, route `docs.spacingmind.com`), not GitHub Pages ([ADR-0051](../docs/decisions/0051-web-demo-mode-and-app-spacingmind-com.md), addendum 2026-11-01).

- **A release** deploys it: `release-please.yml` calls `docs-deploy.yml` with the new tag once the release is published, so production matches the released version.
- **A push to `develop` or a pull request** on the docs paths only builds, tests and checks (`check-dist`); nothing is deployed.
- **By hand**, for any tag, branch or commit (default `develop`):

  ```sh
  gh workflow run docs-deploy.yml -f ref=v0.18.0
  ```

  It needs the repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`; without them the workflow builds and checks the site, prints a notice and skips the deploy.
- **Check the Worker config locally** (no token, no Cloudflare call; `.wrangler/` is ignored):

  ```sh
  npx wrangler@4.156.0 deploy --dry-run --config wrangler.docs.jsonc   # validates the config and reads .vitepress/dist
  npx wrangler@4.156.0 dev --local --config wrangler.docs.jsonc --ip 127.0.0.1 --port 8789   # serves it with its headers
  ```

`_headers` is generated by `.vitepress/config.mts` (`lib/headers.mjs`): never edit it by hand, and never add an inline `<script>` to a page without rebuilding, because the CSP allows only the inline scripts whose hashes it lists.
