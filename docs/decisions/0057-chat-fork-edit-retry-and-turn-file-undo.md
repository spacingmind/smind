# 0057: Chat fork, edit-and-retry, and per-turn file undo

## Status

**Proposed — 2026-11-09.** Extends [ADR-0016](0016-multiple-chats-per-task.md) (a chat is the unit of conversation; chats of a task share its worktree) and the O1 run
provenance (`base_sha`/`head_sha`/`dirty`), uses the native session reader of [ADR-0053](0053-run-skeleton-storage-and-native-history-rebuild.md), and changes nothing in the
policy engine of ADR-0047 or the permission model of ADR-0019. Every choice under [Decisions for the Human](#decisions-for-the-human) carries a recommendation; a veto
changes only the PR named next to it. No code is written before the Human (or the Supervisor under the Human's delegation) answers. Plan to be written with the first PR.

## Context

What a person wants in the middle of a conversation is to **go back**: start a different branch of it from an earlier turn (fork), change an earlier prompt and run it again
(edit-and-retry), or take back the files one turn wrote (undo). smind has the parts, none of the three:

| Fact | Where |
|---|---|
| A chat belongs to a task; its provider session handle is `chats.agent_session` (JSON `SessionHandle{Provider, SessionID, ...}`), read and written through `ChatSessionStore` | `internal/store/schema.sql` (`chats`), `internal/taskrunner/chat_session_store.go`, `session.go` |
| A run is one turn (prompt to answer) of a chat; `runs.chat_id`, `prompt`, `final_text`, `native_ref` (where the provider keeps the session, with the turn window and prompt hash) | schema (`runs`), `internal/history/native/ref.go` |
| The next turn of a chat resumes its session: claude-native via `claudecode.WithResume`, Codex via `thread/resume`, ACP via `session/load` where advertised | `internal/taskrunner/runner.go` (`newClaudeClientWithResume`), `internal/codex/client.go`, `internal/acp/client.go` |
| Chats of one task share the task's worktree and branch, and may run at the same time (the motivating case of ADR-0016) | ADR-0016 |
| A run records the worktree HEAD and a dirty flag at start and end, best effort, with a 3 s git timeout | `internal/runs/provenance.go` (`captureProvenance`) |
| There is **no per-turn commit, checkpoint or content snapshot**: a task checkpoints uncommitted work on archive only | `internal/workspace/archive_branch.go`, `task.go` |
| A chat has no parent: forking and retrying do not exist in the schema or the wire | `chats` table |

What each provider can do natively (checked against the installed tools, not the docs):

- **claude-native.** The CLI takes `--resume <session>`, `--fork-session` and `--resume-session-at <transcript entry uuid>`; the SDK smind vendors exposes them as
  `WithResume`, `WithForkSession` and `WithResumeSessionAt` (`claude-agent-sdk-go` v0.4.2, `client.go`). A fork at a turn is a resume with both flags; the new session id comes
  back at run end like any session. `--resume-session-at` is not in the CLI's public help, so it needs a feature probe and a fallback.
- **Codex.** The app-server protocol (CLI 0.166.0, schema generated by `codex app-server generate-json-schema`) has `thread/fork {threadId, lastTurnId (inclusive), ...}`
  returning a new thread, and `thread/revert {threadId, beforeTurnId}` which drops turns from the replacement history of the **same** thread. Neither is used by smind today.
  `thread/revert` rewrites the conversation in place, so it is not used for retry (below).
- **ACP.** `session/load` is advertised by some agents; a stable fork or rewind is not part of the protocol smind speaks. A fork there is the context-seeded fallback or absent.
- **File effects.** Claude Code's own file checkpointing covers its edit tools and not what a shell command wrote; Codex's revert is a conversation operation. Neither gives
  "the files this turn wrote" for a turn that ran `sed -i`, a formatter or a build. smind needs its own record to promise file undo for every provider.

## Decision

Three features, shipped in this order, each usable without the next: **fork** (a conversation operation), **edit-and-retry** (fork plus a new prompt), **undo** (a file
operation with its own record). They share one anchor, the **turn**, which is a run.

### 1. Data model (additive)

- `chats.parent_chat_id INTEGER REFERENCES chats(id)`, `chats.forked_at_run_id TEXT` (the last run kept), `chats.fork_kind TEXT` (`fork` | `retry`). A forked chat is a normal chat
  of the same task: its own tab, queue (ADR-0021) and `agent_session`, a "forked from <chat> at turn N" line, and the parent's turns up to the anchor shown dimmed as shared
  history. Archiving the parent does not touch the child.
- `runs.tree_before TEXT`, `runs.tree_after TEXT`: git tree object ids of the worktree's contents at the start and end of the turn (§4). `''` = not captured.
- `turn_undos (run_id, undone_at, actor, files_json, outcome)` for audit and to refuse a second undo.
- No backfill: turns before the migration have no record and show no undo. No compatibility shim (no installed base, `feedback_no_users_breaking_ok`).

### 2. Fork

`chat.fork {chatId, atRunId}` (human only, like the other writes of chats): create the child chat, resolve its session by provider.

- **claude-native:** the child's first run launches with `WithResume(parent session) + WithForkSession + WithResumeSessionAt(entry uuid of the anchor turn's last assistant
  entry)`; the new session id is stored as the child's `agent_session` at run end. The entry uuid comes from the transcript through the ADR-0053 reader, which today walks the
  records but does not return each turn's entry uuids; adding that is part of PR 1. A transcript that is gone or fails the reader's self-check refuses the fork with the reader's
  `Reason` (`native_session_missing`, `format_drift`), and the UI offers the fallback.
- **Codex:** `thread/fork {threadId, lastTurnId}` with the anchor turn's id (also read from the rollout by the reader), then the usual `thread/resume` in the child's runs.
- **ACP and any provider that cannot fork:** the **context-seeded fallback**: a new chat whose first prompt carries the earlier turns' prompts and final texts (bounded, from the
  stored run rows, never the provider's session), marked `lossy` in the UI ("the agent does not remember tool calls or its reasoning"). Hidden for an agent that is a plugin
  provider.
- A fork never reads or writes the parent's session file: `--fork-session` and `thread/fork` copy. The parent keeps working.
- Refused while the parent chat has a running run (the session file is being written; the reader already refuses with `native_session_in_use`).

### 3. Edit-and-retry

"Edit" a user prompt of turn N and run it: **fork at turn N-1, then send the edited text** in the child. "Retry" is the same with the original text. The parent chat keeps turns N
onward untouched (non-destructive; nothing is deleted or rewritten, and the original stays one click away). In-place history rewrite (`thread/revert`, dropping a turn) is not
offered: it destroys the only copy of the conversation, and no provider has it for all three harnesses.

The **files** stay as they are. The child agent starts from the conversation of turn N-1 in a worktree that already holds the effects of turns N and later. smind says so on the
fork banner and offers undo (§4) for the turns being replaced as a first step; it does not undo for the person. A later option, not built here, forks into a **new task** whose worktree
is created at the turn's `tree_before` snapshot (D3).

### 4. Per-turn file undo

**Record.** At the start and end of a user run in a git worktree, `captureProvenance` also writes the worktree's content as a git tree object, without touching the user's index,
HEAD or working files: copy the index to a temporary file, `GIT_INDEX_FILE=<tmp> git add -A`, `git write-tree`, delete the temporary index. The objects are anchored by a ref under
`refs/smind/turns/<runId>/{before,after}` so `git gc` keeps them, and the refs are deleted with the run's retention (ADR-0053's prune). The capture respects `.gitignore` (build
output and `node_modules` are not part of a turn), has its own timeout and size cap (a worktree over the cap records nothing and the turn shows "undo unavailable: too large"),
never changes the run's status, and logs one line on failure, like the existing capture. A secret-denied path (`internal/secretdeny`) is never restored or shown.

**What a turn wrote** is `git diff-tree before after`: the paths whose content differs, with their blob ids. A turn that ran while another run of the same task was running
(overlapping `started_at`..`finished_at` windows) is flagged `shared_worktree`, because the diff cannot say whose write it is.

**Undo** (`turn.undo {runId, dryRun?}`, human only). For each path the turn changed, compare the **current** file with the turn's **after** blob:
- equal: restore the **before** blob (delete the file if the turn created it, recreate it if the turn deleted it, restore the mode);
- different, missing where the turn left a file, or a file where it left none: the file **changed since the turn** (a later turn, another chat, the person, a formatter on save).
  **Refuse.** Never overwrite it.

The default is **atomic**: if any path is refused nothing is touched, and the answer lists every path with its reason, so the person can resolve it (undo the later turn first, or
revert by hand). Undo is therefore stack-like per file: turn N's undo is refused while turn N+1 edited the same file. The dry run (also what the UI shows before the confirm) returns
the same list without writing.

Further refusals, each with its own reason code: `no_record` (before the migration, or not captured), `run_active` (a run of the task is writing), `shared_worktree` (another run
overlapped; allowed only with `confirmShared`, which shows the paths), `head_moved` (HEAD is not the turn's `head_sha`: a commit or reset happened since), `turn_committed` (the turn
itself moved HEAD: `base_sha != head_sha`; history is not undone here, use git), `already_undone`, `too_large`, `secret_path`.

**What it never does:** touch a path the turn did not change, discard uncommitted changes of the person (a changed file is a refusal), touch the index or HEAD, run a git command that
writes history, write outside the worktree (every path is resolved and checked against the worktree root; symlinks are restored as symlinks, never followed), or run an agent. It
does not undo effects outside the worktree (installed packages, a database, a pushed commit or an open PR): the confirm text says so.

**Pull requests and commits.** Undo changes the working tree, so a task with an open PR shows the result as uncommitted changes against the branch head; nothing is pushed. If the
person committed after the turn, `head_moved` refuses: they revert with git, which is the right tool for history.

### 5. Surfaces

- **Web:** a turn menu (fork from here, edit and retry on a user prompt, undo files on a turn that wrote files); the undo confirm lists the files and the refusal reasons; the fork
  banner; chat tabs show the fork parent. **Mobile:** the same actions in the turn's action sheet, narrow style. **CLI:** `smind chat fork <chatId> --at <runId>`,
  `smind task retry <chatId> <runId> [--prompt ...]`, `smind turn undo <runId> [--dry-run]`.
- Inbox/notifications: none. These are human actions, never an agent's: all three RPCs are refused to run-scoped connections and are not MCP tools (a handler-map test, as for the
  other human-only methods; see ADR-0056 for what "human" means on the socket).
- Light and dark frames for each state on web and mobile are part of the UI PRs.

### 6. Failure modes

| Failure | Result |
|---|---|
| The provider cannot fork (no transcript, probe fails, ACP) | fork refused with the reason; context-seeded fallback offered, labelled lossy |
| The CLI renames or drops `--resume-session-at` | the probe fails at start: fork shows the fallback only, with a daemon log line |
| Worktree capture fails or times out | the turn has no record; undo shows `no_record`; the run is unaffected |
| Two chats write the same file | undo refused (`shared_worktree` or changed since) |
| The person edits a file between dry run and confirm | the real run re-checks every path under the same lock; a change refuses the whole undo |
| Daemon restarts during an undo | the undo writes files one by one from the before blobs; an interrupted undo is detected by the next dry run (some paths already equal `before`) and reported as `partially_undone`, completable by running it again |
| Disk | tree objects are deduplicated by git; refs are pruned with run retention; a size cap per capture |

## Options considered

- **Rely on each provider's own rewind.** Rejected for files (partial and tool-specific, §Context) and for retry (in place, destructive, not on all providers). Used for conversation
  fork where the provider has it.
- **Commit every turn to the task branch.** Rejected: it pollutes the branch the person reviews and ships, and the dirty-tree case needs commits the person did not ask for.
- **A shadow git repository of the worktree.** Works, but doubles object storage and needs its own gc; the temporary-index tree capture reuses the worktree's own object store.
- **Snapshot by copying files.** Rejected: slow for big trees, no dedup.
- **Fork into a new worktree by default.** Faithful, but heavy and it splits the task; offered later (D3).

## Consequences

- Fork and retry are available for Claude and Codex chats whose session file the reader can use, and as a labelled fallback elsewhere; undo is provider-independent for tasks in a git
  worktree.
- Two columns on `runs`, three on `chats` and one table; capture adds up to two `git add -A`/`write-tree` passes per user turn, bounded and best effort.
- Git refs under `refs/smind/turns/` appear in the repository (hidden from branch lists); they are removed with run retention and with the task's archive.

## What we are NOT doing

- Not rewriting or deleting conversation history in place.
- Not undoing commits, pushes, PRs or anything outside the worktree.
- Not committing, stashing or touching the index or HEAD for a snapshot.
- Not exposing fork, retry or undo to any agent, orchestrator or MCP tool.
- Not building the fork-into-new-task option or a partial undo in the first PRs.

## PR split

1. Fork for claude-native and Codex: schema (`chats` columns), the reader returning each turn's entry uuid / turn id, `chat.fork`, the probe, the fallback, web + CLI; mobile in 1b.
2. Edit-and-retry on top of fork: web, mobile and CLI.
3. Snapshot capture: `tree_before`/`tree_after`, refs, retention, the capture tests against real git in a temp repo.
4. Undo: `turn.undo` with the dry run and every refusal, then web, mobile and CLI.

Each PR carries light and dark frames for its states and the human-only handler-map test.

## Decisions for the Human

- **D1: file-undo record.** Recommendation: tree snapshots under `refs/smind/turns/`, as in §4 (provider-independent, no branch noise). Alternative: the provider's own file rewind (Claude only, edit tools only).
  Veto changes PR 3.
- **D2: undo when part of the turn's files changed since.** Recommendation: atomic (refuse the whole undo and list why). Alternative: undo the files that still match and list the rest (partial). Veto changes PR 4.
- **D3: edit-and-retry file fidelity.** Recommendation: conversation fork in the same task, files stay as they are, undo offered first. Alternative: also fork into a new task at the turn's snapshot.
  Veto changes PR 2 and adds a PR after 4.
- **D4: forks on ACP and other providers without a native fork.** Recommendation: the labelled context-seeded fallback. Alternative: hide fork and retry for them.
- **D5: size cap for a worktree snapshot.** Recommendation: 20 000 paths or 500 MiB of changed content per capture, beyond which the turn records "undo unavailable". Alternative: no cap.
- **D6: a turn that committed.** Recommendation: refuse undo (`turn_committed`), the person uses git. Alternative: offer a revert commit (writes history; not recommended).
