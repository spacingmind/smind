## Decisions (all five accepted by the Human, 2026-11-15)

- **D-A WebSocket/WebTransport: PROXY.** An in-process enforcing proxy in the daemon (PR 1b below), all schemes through one policy check, empty bypass list, names resolved by the proxy and the connection pinned to the resolved IP. No tool PR before it lands.
- **D-B The daemon gates tool calls.** The call is held and approved inside the daemon whatever the provider's permission mode (PR 4); provider-native prompts are a second layer only.
- **D-C Ship with the stated ADR-0056 limit.** The enable method is as human-only as the principal today (an unidentified local connection counts as the human); the floor rule and CLI refusal cover the common routes. The Settings text and the PR bodies state the limit.
- **D-D Every acting tool asks; `browser_open` may be granted for the CURRENT RUN on its card.** No grant outlives its run and no "always" scope exists; every other acting tool asks every call.
- **D-E Allowlist: loopback plus exact hosts the human adds**, validated by `NormalizeAllowHost`; link-local and metadata addresses can never be allowed.

The reasoning behind each is in ADR-0061's amendment of the same date. The 12 decisions of the ADR are unchanged.

## PR 1b: an enforcing forward proxy for the session

Goal: every network connection the browser makes (document, subresource, WebSocket, worker, fetch from script) is vetted by `Policy` at connect time, and the proxy dials the vetted address itself.

- **Component.** `internal/browser/proxy.go`: a per-session HTTP proxy on `127.0.0.1:0` (HTTP absolute-form requests and `CONNECT host:port`, which a browser uses for https and for WebSocket through an HTTP proxy, as measured below). The launcher adds `--proxy-server=http://127.0.0.1:<port>` and `--proxy-bypass-list=<-loopback>` (removing the browser's implicit bypass of localhost/127.0.0.1/[::1]; measured below: an empty list does not do this), and drops `--no-proxy-server`.
- **Decision per connection.** Parse the target (`host:port`) with the same `parseHost` as URLs, run the `CheckURL`-equivalent plus `CheckResolved`, resolve once in the proxy, refuse if any address is sensitive or denied, then **dial the vetted IP:port** (not the name). That closes the DNS-rebinding window between our lookup and the browser's, and it enforces `Deny` for IP literals and WebSockets. The proxy's own port and the daemon's are in `Deny` (the session adds the proxy port).
- **No TLS interception.** `CONNECT` is a blind tunnel after the host/port check; the policy is host-level, so nothing needs the plaintext.
- **Not an open relay.** Loopback listener only; a request to any target the policy refuses gets `403` with a reason and no dial. A local process using it can reach only what it could reach directly.
- **Limits.** At most 64 concurrent connections per session, a 10 s dial timeout per vetted address (so a blackholed first address does not use up the next one's budget; amended from the draft's 30 s), a 5-minute tunnel idle timeout on one shared clock for both directions (an upload-only tunnel stays alive while the client sends; a silent one is closed on both sides), a 60 s bound on any single read or write on the forward path, a 64 KB cap on upstream response headers, header size cap via `net/http`, hop-by-hop headers stripped, absolute-form with userinfo refused, `Proxy-Authorization` ignored.
- **Browser flags kept.** Host-resolver MAP rules stay as defence in depth; WebRTC non-proxied UDP stays disabled; QUIC/WebTransport are refused by the browser once a proxy is set (measured below), with `--disable-quic` as defence in depth.
- **Measured (installed Chrome, headless, a logging proxy that answers everything itself, nothing left loopback; program and raw output under the dogfood root):**
  1. With no bypass flag, **and with an explicitly empty `--proxy-bypass-list=`** (so an empty list is NOT what is implemented; the flag is exactly `<-loopback>`), loopback traffic (`127.0.0.1`, `localhost`, `*.localhost`, `[::1]`) never reaches the proxy: Chrome bypasses it implicitly. Only `--proxy-bypass-list=<-loopback>` sends it through. So "an empty bypass list" is implemented as exactly `<-loopback>` (which removes the implicit bypass and adds nothing), and a launcher test pins it.
  2. With `<-loopback>`, `fetch` to an IP literal, `*.localhost`, `localhost` and `[::1]` arrive as `GET http://host:port/...` (absolute form); `ws://` and `wss://` (IP literal and `*.localhost`) arrive as `CONNECT host:port`. So one proxy decision on `host:port` covers every scheme; the handshake never reaches the page's target unless the proxy dials it.
  3. WebTransport (only exists in a secure context, e.g. `http://localhost`): with a proxy set, no request reaches the proxy and **no UDP datagram arrives** at the target port (a UDP listener on the target saw nothing); the page gets a connection error. So WebTransport/QUIC is refused by the browser itself while a proxy is configured; a launcher flag (`--disable-quic`) is kept as defence in depth.
  4. The browser's own background traffic (update and time services) also goes through the proxy; the proxy refuses it under the same policy (no extra allowlist for it).
- **Tests.** Table test of the proxy decision against the same URL table; real listeners: an allowed target is tunnelled, a denied loopback port gets 403 and zero hits, a rebinding resolver (first answer allowed, second a denied address) is pinned to the first, `CONNECT` to a denied IP literal is refused, oversize or garbage request lines are closed. The PR 1 smoke test **flips**: its `KNOWN GAP` log becomes the assertion "WebSocket and `fetch` to the denied port get zero hits".
- **Mutations.** the proxy dials the name instead of the vetted IP; policy skipped on `CONNECT`; deny list skipped for IP literals; bypass list not `<-loopback>` (loopback skips the proxy); proxy port not denied.
- **Size and risk.** One PR, daemon only, about 600 lines plus tests; high risk (network boundary); two-sub-agent review plus the Steward's own.

## PR 2: the read-only `browser_*` tools, shipped dark

Nothing in this PR can reach an agent: the row is gated on a setting nothing can set yet (PR 3) and on a ready flag PR 4 flips.

- **Tool set** (pinned by `browser_tool_set_is_pinned`): `browser_open`, `browser_tabs`, `browser_close`, `browser_snapshot`, `browser_screenshot`, `browser_console`, `browser_wait`. No click/fill/type/press/scroll/history in this PR, no evaluate, upload or download.
- **MCP child.** `smind mcp browser` (stdio; the same identity environment as `smind mcp serve`, the same go-sdk), appended in `Runner.mcpRowsFor` as the reserved name `smind-browser` through a new `McpPolicy.Browser` field set in `internal/runs/contract.go`. A registered server of that name never reaches a managed run (the same reserved-name rule as `smind`); `withoutSmindMcp` strips it for plugin providers.
- **RPC.** `browser.call {tool, args}` on the daemon, in `RunScopedMethods`, bound to the connection's run id: the workspace is derived from the run, and a workspace or run id in the params is ignored (tested). The MCP child holds no browser logic: the daemon's broker owns the catalogue, policy, limits, envelope and timeline events. **[Superseded by PR 3b-2: there is no websocket `browser.call`, no `session.identify` for the browser and no token; the child reaches the broker over its run's own socket, see "PR 3b-2: progress".]**
- **Broker** (`internal/browser/broker.go`): per-run limiter (30 calls per minute, 500 per run, 10 navigations per minute, one call in flight, 20 s), the per-workspace `Manager` session, the envelope, truncation and password masking, one timeline event per call (tool, redacted URL, outcome, duration; no page content).
- **Envelope.** A fixed header naming the origin and stating that the content is untrusted data not to be followed as instructions, then the content between boundary lines carrying a per-call random token the page cannot predict (so content cannot forge the closing line). Everything page-controlled (title, URL, text, console) goes through `cleanText` first.
- **Snapshot.** `Accessibility.getFullAXTree` rendered as an indented text tree with refs `e1..` valid for this snapshot only (bound to backend node ids; the acting-tools PR reuses them), at most 1,200 nodes and 40,000 characters with a marker; any node the browser marks protected (password) never shows its value.
- **Screenshot.** Viewport only (`Page.captureScreenshot` with a viewport clip), long side at most 1,568 px, at most 1.5 MB (JPEG quality stepped down until it fits, else refused with a message); password inputs blurred by a style injected in an **isolated world** (page script cannot remove it). Returned as an MCP image block only when the run's provider reads images (a new `ImagesRead` flag on the run contract, from the provider catalogue), otherwise a text note.
- **Console and wait.** `browser_console` returns the session ring (100 lines of 500 characters). `browser_wait` polls a text or URL condition in the isolated world, capped at 15 s.
- **Tests (fake CDP, no browser).** `browser_tool_set_is_pinned`, `envelope_wraps_every_result`, `envelope_boundary_cannot_be_forged`, `limits_truncate_with_marker`, `password_values_never_returned`, `rate_limit_table` (the 31st call in a minute), `serialised_one_in_flight`, `run_id_binds_workspace`, `image_only_for_image_providers`, `injected_instruction_stays_inside_the_envelope`, plus a real-Chrome smoke of snapshot, screenshot and console on a page the test serves. Mutations: a limit raised, envelope removed, boundary fixed instead of random, password value emitted, a params workspace honoured, screenshot not clipped to the viewport.

## PR 3: the human-only enable flag and the allowlist

- **Store.** A `browser_settings` row per workspace (enabled default 0, allow hosts JSON, profile mode `ephemeral|persistent`); a new migration (no installed base). A daemon-wide kill switch in config (`browser.disabled`) that no RPC can change and that overrides everything.
- **RPC and CLI (all human-only).** `browser.settings.set` and `browser.data.clear` on `permpolicy.HumanOnlyRPCs`, refused for run-scoped callers, never in `RunScopedMethods` or the MCP tool list; `browser.settings.get` is also human-only (the allowlist is configuration, not an agent's business). CLI `smind browser enable|disable|allow add|allow rm|clear` joins `humanOnlyCLI` (`status` stays read-only). Drift tests: `TestHumanOnlyRPCTable_MatchesHandlers` gains the names, a new test walks the handler map and MCP list for them, the golden method map is regenerated.
- **Gate.** The row is appended only when: the workspace switch is on, the kill switch is off, the run contract allows it, a host is available (`DetectChrome` ok), and the PR 4 ready flag is set. `browser_row_present_only_when_all_gates_hold` and `codex_native_gets_no_row` pin it.
- **Policy input.** `NormalizeAllowHost` on every entry; the `Deny` list is filled from the daemon's own listen address, the proxy origin and the connection list (and the proxy port in 1b); changing any of it closes the workspace session (`Manager.Close`).
- **Limit stated:** D-C.

## PR 4: permission integration (read grantable per run, acting asks every time)

Recommended design (D-B): the daemon gates, independent of the provider's permission mode.

- **Classes.** READ: `browser_snapshot`, `browser_screenshot`, `browser_console`, `browser_tabs`, `browser_wait`. ACT: `browser_open` and every later acting tool.
- **Read grant.** The first read call of a run blocks (bounded, default 5 minutes) while the daemon raises one card to the human through the existing permission/question channel (web, mobile push, inbox; ADR-0055): "Allow this run to read pages in the browser (snapshot, screenshot, console)?" with the workspace's allowlist shown. The answer is a human-only RPC `browser.grant.answer {runId, requestId, allow}`; allow stores an in-memory per-run grant (gone when the run ends, never saved across runs). Deny or timeout returns a plain tool error "not permitted by the person".
- **Acting calls.** Every call raises its own card (tool, target label or URL with the query dropped, the ref's role and name) and waits; no "always" scope exists. If D-D is yes, the `browser_open` card offers "allow navigation for this run" as a per-run grant limited to the policy's destinations.
- **Provider layer.** The policy engine may additionally carry `mcp:smind-browser.<tool>` rules (exact names, no wildcards) so a provider that asks natively stays consistent; the daemon gate never relies on it.
- **Tests.** `read_blocks_until_granted`, `act_asks_every_call`, `grant_dies_with_the_run`, `deny_and_timeout_return_plain_error`, `answer_is_human_only` (RPC principal, handler map), `no_always_scope_exists`, and a test that runs under a provider bypass mode and still blocks. Mutations: an acting tool allowed with a read grant, a grant surviving the run, the answer RPC callable by the MCP principal, the gate skipped when the provider mode is auto.
- **Ready flag.** This PR flips the flag PR 3 gates the row on; before it merges no agent can receive the row.

## PR 1b: progress and validation

Built as designed, with these decisions made while building (all from the measurements and the two reviews):

- **Bypass rules exactly `<-loopback>`**; measured on the installed Chrome that it also removes the implicit bypass of link-local and private addresses (a page `fetch` and `ws://` to `169.254.169.254` and `[fe80::1]` reached the proxy), so one policy check covers them. The smoke asserts the proxy refused the link-local target.
- **`localhost` and `*.localhost` are not sent to DNS** (RFC 6761): the proxy dials `127.0.0.1` and `::1` directly. A page-chosen name cannot leave the machine as a DNS query, and no resolver can disagree. `CheckResolved` for such a name still exists (policy table tests) but the proxy and the session's Fetch check do not call it.
- **Every connection re-vets and re-dials**: no upstream connection reuse (`DisableKeepAlives`), the vetted address is carried in the request context, redirects are not followed (the browser follows them and each hop is vetted again).
- **Proxy refusals are reported once per target** (query and userinfo removed, sanitised, a rolling window of 200 targets), because the browser's own background requests (update and time services) are also refused and must not flood the agent's notices. A set of Chrome flags quiets most of that traffic; the rest is refused and reported once.
- **More sensitive IPv6 forms**: IPv4-translated `::ffff:0:0:0/96`, deprecated site-local `fec0::/10`, local-use NAT64 `64:ff9b:1::/48` and Teredo `2001::/32` are refused (allowlist entry and resolved name).
- **Allowlisted NAMES must resolve public (review round 2).** A name the human adds may only resolve to public addresses; loopback, private (RFC 1918, unique-local), CGNAT, `0/8` and other internal results (including NAT64/6to4/IPv4-compatible forms embedding one) are refused for such a name, because its DNS is not ours: an attacker-influenced record is how a name reaches the daemon's machine or the LAN. To allow an intranet host the human adds its **IP literal** (an exact entry). The later Settings text must say so next to the allowlist editor.
- **Accepted residual: the proxy is an unauthenticated loopback service.** It is MORE than the caller could reach directly in one respect: for an allowlisted host (an IP literal the human added, say an intranet host) the proxy dials from the daemon's network position, so any local process that can reach the proxy can reach that host through it, which a sandboxed process (a localhost-only network sandbox) could not do directly. Any other OS user on the machine can also use it; the port is discoverable (`lsof`), and `Proxy-Authorization` is ignored. Loopback targets add nothing (reachable directly), and the daemon, the proxy and metadata addresses stay denied. What does NOT work against it: a web page in the person's own browser cannot abuse it (a browser cannot send `CONNECT` or an absolute-form request to a proxy it was not told to use, and an origin-form request gets `400`). **Closed in PR 3b-1**: the proxy requires a per-session `Proxy-Authorization` secret (see "PR 3b-1: progress" below). The text that follows is the residual as it stood for PR 1b. The Settings text must state this next to the enable switch.
- **Connection accounting.** There is no upstream connection reuse (each request dials afresh through the policy). Browser-to-proxy keep-alive connections are closed after 5 s idle so they cannot hold the 64-connection cap; a tunnel one side closed is closed on both sides after a 10 s grace; an upload-only tunnel stays alive while the client sends.
- **Known lows (accepted).** (1) A client that drips a request body one byte per IO window renews the per-read deadline for ever: it holds one connection slot, bounded by the 64-slot cap and the per-session lifetime, not by a total time. (2) After one side of a tunnel closes, the other direction gets a hard **10 s** to finish and is then cut, even if it is still moving data (a client that half-closes after its request and waits for a long streamed answer would be cut): the browsers in use close fully, so this is deliberate, and it is what keeps a closed client from pinning a slot. (3) When the upstream answers before the client finished its body, the proxy answers with `Connection: close` and does not read the rest; a stalled client body is cut at the IO window even if the response is still streaming.
- **Startup traffic.** Refusals that happen before the session object exists (the browser's own first requests) are not reported to the agent, by intent; later refusals are reported once per target.
- WebSocket and WebTransport: refused as measured (CONNECT, and no UDP datagram under a proxy); `--disable-quic` is kept as defence in depth.

Validation: `go test -race` on the package, the real-Chrome smoke (the page's WebSockets, `wss`, fetches, a link-local fetch and a WebTransport attempt: zero hits on the denied port and zero UDP datagrams, with the proxy's refusals observed first), `task test` with `TMPDIR` outside the daemon home, `GOOS=windows`/`linux` vet. Not verified: Linux and Windows Chrome were not measured; the Windows pipe/Job Object path is unchanged and still unrun.

## PR 2: detailed spec and acceptance criteria (the read-only tools, shipped dark)

Starts from a fresh `origin/wave/desktop` after PR 1b (#949, the proxy) has merged. High-risk (a new RPC surface reachable by an agent's MCP child, page content entering a model's context): foreground two-sub-agent review, the Steward's own review, a real-Chrome smoke, mutations. One PR.

### What exists to build on (read from the code)

- `internal/browser`: `Policy`, `Session` (tabs with a 3-page pool, `Navigate`, `Tabs`, `CloseTab`, `Console`, `DrainNotices`), `Manager` (one session per workspace, 2 daemon-wide, idle close 5 min), the enforcing proxy, the CDP `Client` (pipe transport).
- The MCP child pattern: `cmd/smind/mcp.go` `cmdMcpServe` identifies as the run with `session.identify {runId}` from `SMIND_RUN_ID` and serves a go-sdk server whose tools call the daemon over the websocket; the reserved row is built in `Runner.mcpRowsFor` (`internal/taskrunner/mcp.go`) from `McpPolicy` (`internal/taskrunner/run_contract.go`), set in `internal/runs/contract.go`. **[Superseded by PR 3b-2: there is no websocket `browser.call`, no `session.identify` for the browser and no token; the child reaches the broker over its run's own socket, see "PR 3b-2: progress".]**
- `RunScopedMethods` (`internal/wsapi/session.go`) is the closed list an identified (agent) connection may call; every other method refuses it.
- Provider catalogue: `internal/providers/providers.go` `Images: "yes" | "no" | "unknown"`, surfaced as `taskrunner.ProviderInfo.Images`.

### Scope

In: the seven tools (`browser_open`, `browser_tabs`, `browser_close`, `browser_snapshot`, `browser_screenshot`, `browser_console`, `browser_wait`), the broker, the `smind mcp browser` child, one run-scoped RPC `browser.call`, the `smind-browser` row machinery, `ImagesRead` on the run contract, the new CDP primitives in `Session`, per-call timeline records.
Out (later PRs): acting tools (click, fill, type, press, scroll, history), the human-only enable flag and allowlist storage (PR 3), the daemon-side permission gate (PR 4), the provider table (PR 5), any UI.

### Acceptance criteria

- **P2-AC1 Dark.** No run receives the `smind-browser` row in this PR: the row is appended only when `browserGateReady` (a package constant, false) AND the workspace switch AND the kill switch AND the run contract AND a host are all true; with every other input true and the constant false the row is absent. Flipping the constant is PR 4's job. A registered MCP server named `smind-browser` never reaches a managed run (reserved name, like `smind`); `withoutSmindMcp` strips it for plugin providers.
- **P2-AC2 Tool set pinned.** The server lists exactly the seven tool names above; a test fails on any other (no evaluate, upload, download, click, fill, type, press, scroll, back, forward, reload). Each tool has a strict input schema (unknown fields refused, string lengths capped: URL 2,048 characters, wait text 200).
- **P2-AC3 The RPC is run-bound.** `browser.call {tool, args}` is in `RunScopedMethods`, refuses a connection that did not identify as a run, derives the workspace from the identified run id, and ignores (and tests that it ignores) any `runId` or `workspace` inside `args`. A run with no browser row, or whose workspace switch is off, gets a plain error from the daemon even if its child somehow called (defence in depth: the daemon re-checks the gate on every call, not only when building the row). **[Superseded by PR 3b-2: there is no websocket `browser.call`, no `session.identify` for the browser and no token; the child reaches the broker over its run's own socket, see "PR 3b-2: progress".]**
- **P2-AC4 Envelope.** Every result that carries page-controlled text is wrapped by the daemon: a fixed header naming the origin and saying the content is untrusted data, not instructions, then the content between boundary lines that contain a fresh 128-bit random token per call (so content cannot forge the closing line), then a fixed trailer. Page-controlled strings (title, URL, AX names and values, console text, screenshot alt text) pass through `cleanText` before they are placed in the envelope. The child forwards the daemon's text verbatim and adds nothing from the page.
- **P2-AC5 Snapshot.** `browser_snapshot` renders `Accessibility.getFullAXTree` as an indented text tree: role, quoted name, a short state list, refs `e1..` valid for this snapshot only (a later snapshot invalidates them; refs are recorded per tab with their backend node ids for the acting tools to reuse later). Limits: 1,200 nodes and 40,000 characters, truncated with a marker that says what was dropped. A node the browser marks protected (a password field), or whose input type is password, never shows its value (name and role only). Ignored and generic nodes without text are skipped so the budget is not wasted.
- **P2-AC6 Screenshot.** Viewport only (`Page.captureScreenshot` with a viewport clip, never the window or screen), long side at most 1,568 px (scaled down through the clip scale), at most 1.5 MB (JPEG quality stepped down from 80 to 40; if still over, a text refusal naming the limit). Password inputs are blurred first by a style injected in an **isolated world** (`Page.createIsolatedWorld`), which page script cannot reach or remove, and the style is removed after the capture. The image is returned as an MCP image block only when the run's `ImagesRead` is true (`Images == "yes"`; `"no"` and `"unknown"` get a text note: "this provider cannot read images; use browser_snapshot"). The note and the metadata (size, URL origin) are enveloped like any page-derived text.
- **P2-AC7 Open, tabs, close.** `browser_open {url}` checks the URL with the policy BEFORE sending (a refusal is a plain tool error with the reason), navigates the run's first tab (creating it inside the pool), and returns title, final URL (after redirects) and the notices since the last call. `browser_tabs` lists the pool (id, title, URL, current marker). `browser_close {tab}` closes one tab; closing the last tab leaves the session idle, not closed. Titles and URLs are cleaned and enveloped.
- **P2-AC8 Console and wait.** `browser_console {}` returns the session's ring (at most 100 lines of 500 characters) enveloped, oldest first, and does not clear it. `browser_wait {text|url, timeoutSeconds}` waits for a text (found by an isolated-world `innerText` check, never page-defined code) or a URL substring, polling every 250 ms, with the timeout capped at 15 s; on timeout it returns "not found within N s" and the current URL, not an error.
- **P2-AC9 Limits and one in flight.** Per run: 30 calls per minute, 500 per run, 10 navigations (`browser_open`) per minute, one call in flight (a second concurrent call waits, FIFO, and is refused if it would wait longer than the call timeout), 20 s per call (the call's context). A refusal returns a plain error naming the limit and does not count as a call that reached the browser. The counters reset with the run, never across runs.
- **P2-AC10 Notices.** The broker appends the session's drained notices (blocked requests, dialogs cancelled, downloads denied, popups refused) to the next result, inside the envelope's "browser notices" section, each already sanitised.
- **P2-AC11 Timeline.** Every call produces one run-timeline record carrying the tool name, the redacted URL (no query, no userinfo), the outcome (ok, refused: reason, error, limit: name) and the duration; never page content. (Implementation note, to settle while building and report in the PR: whether the daemon's run event log already accepts an appended record for the run from a handler; if it does not, the provider's own tool-call event carries the call and the broker adds a `browser.call` record through the smallest registry addition, stated in the PR.)
- **P2-AC12 Lifecycle.** A session is started on the first call of a run (`Manager.Get`), and is closed when the run ends (a registry hook; tested), when the human stops the task, and by the idle timeout; the daemon shutdown calls `CloseAll`. Starting fails with the plain "no browser installed" text and the install step when `DetectChrome` finds none, and with the "too many browser sessions" error at the daemon-wide cap.
- **P2-AC13 No new human-only surface, nothing granted.** This PR adds no human-only RPC, no setting, no CLI. `browser.call` is not on `permpolicy.HumanOnlyRPCs`; a test asserts it is on `RunScopedMethods`, refuses an unidentified connection, and is absent from the MCP tool list of the `smind` server. **[Superseded by PR 3b-2: there is no websocket `browser.call`, no `session.identify` for the browser and no token; the child reaches the broker over its run's own socket, see "PR 3b-2: progress".]**

## PR 2: progress, decisions taken while building, validation

Built against the PR 2 spec (#953), shipped dark: no run can receive the `smind-browser` row (`browser.GateReady` is a constant `false`, `TestGateIsDarkUntilThePermissionGatePR` pins it, and PR 4 is the only PR that flips it), and the daemon refuses every `browser.call` unless the gate is open AND a workspace switch hook says yes (no such hook is installed yet).

Decisions taken while building (none architectural; each differs from or refines the spec text):

- **Screenshot redaction is done by the daemon, not by a style in an isolated world.** The DOM is shared between worlds, so a `<style>` element injected from an isolated world can still be found and removed by page script; the spec's claim that page script cannot remove it was wrong. Instead the password inputs are located through the DOM domain (no page script runs), the viewport is captured as PNG, and the daemon paints those boxes over with solid gray (stronger than a blur) before encoding the JPEG. Failing to locate the fields (any error but "no box model", which means a hidden input) refuses the screenshot. Verified against a real Chrome: the field region is gray at the right place (viewport CSS pixels, scaled), the rest of the page untouched.
- **The image flag is computed per call from the provider catalogue (`Images == "yes"`), not carried on the run contract**: the daemon decides at call time and the child cannot spoof it. `"no"`, `"unknown"` and anything else get the text note.
- **The snapshot walk is depth-bounded** (100 levels): a hostile page can nest nodes without limit and a Go stack overflow would take the daemon down. The truncation marker counts what was dropped.
- **The agent keeps working in the tab it navigated** (`current`), and the first navigation waits (up to 2 s) for the browser's own blank page instead of opening a second tab; found by the real-Chrome smoke (a snapshot of the wrong, blank tab).
- **The registered-name rule is stronger than for `smind`:** a registered MCP server named `smind-browser` is dropped for EVERY run (managed or not), and plugin providers get neither built-in row; `browser.` is on the plugin never-prefix list.
- **Timeline:** one `NoteRunEvent` registry method (a session note on the live run) carries the line `browser <tool> <redacted url> -> <outcome> (<ms> ms)`; no page content.
- **Staffing:** the snapshot and wait primitives (peer A) and the `smind mcp browser` child (peer B) were written by GLM peers from step-by-step briefs and reviewed and integrated by me; the broker, the RPC, the gate, the screenshot, the registry and runner changes are mine.

Validation: fake-CDP tests for every primitive and the broker, a real-Chrome smoke of the read tools through the proxy (snapshot without the password value, a decodable JPEG within the caps with the password region painted over, console, wait success and soft timeout, a public host refused), run-scoped RPC tests through an identified connection, mutations for each security property. Not verified: Linux and Windows Chrome; a real daemon end to end (nothing can reach the tools while dark); snapshot password detection covers `input[type=password]` found through the DOM, not a password field inside a shadow root or an iframe of another origin.

### PR 2: review round (two fresh sub-agents), fixed in this PR

- **A run id is not an identity.** `session.identify` accepts any running run id and `run.list` shows them, so `browser.call` is now also bound to a per-run capability: a 128-bit token minted when a run's browser row is built, delivered only in that row's environment (`SMIND_BROWSER_TOKEN`, the MCP child's, not the agent's own), sent by the child with every call, checked in constant time, dropped when the run ends. A run that got no browser row (system runs, validators) has none and is refused. The call also needs `rc.ident.runID != ""` and a run that is still running. This is a drift guard like the daemon token itself (an agent with a shell can read a same-user process environment on some systems), not a sandbox; it stops a bare "claim another run's id". **Superseded in PR 3b-2: the token, the websocket `browser.call` and `session.identify` for the browser are gone; the child reaches the daemon only through its run's own socket, whose peer check admits only a process of the run's tree (see "PR 3b-2: progress" below).**
- **No resurrection after a run ends**: the broker remembers the last 4,096 ended runs; a late call is refused (no counters recreated, no session started), and a session that was being started when its run ended is closed. The owner of a workspace session is recorded before the session is requested.
- **Counting and time budget**: a call is counted only once it has its turn (a call refused for waiting too long is not counted); the whole call (waiting for its turn included) has one 20 s budget; `timeoutSeconds` 0 means the default (15 s) and says so.
- **Screenshot redaction no longer assumes a device pixel ratio of 1**: the delivered image size is checked against the requested viewport; an image larger by the ratio is captured again at the corrected scale; anything still not the requested size is refused; the rectangles are placed with the delivered size. More than 100 password inputs (decoys) refuse the screenshot and the snapshot instead of covering only the first 100. Nothing below a password node is shown in a snapshot, and a quote in a page string is escaped so it cannot close the quoted field.
- **Timeline lines carry only the origin** (a page picks its own paths; supervisors read the timeline). The envelope header says an attached image is page content too.
- **Accepted, documented, not built** (all low; the first and the shared-session items of the original list were fixed in the second review round below): a password field inside a shadow root or an iframe is not located by the DOM scan (Chrome itself masks its accessibility value as bullets, measured, so the snapshot shows only its length, but the screenshot shows the bullets); a field a page re-types to `text` is indistinguishable from an ordinary field; `Page.createIsolatedWorld` runs on each `browser_wait` (at most 500 per run).

### PR 2: second review round (Steward 5), fixed in this PR

- **A hostile page can no longer end its own session with a big reply.** An over-cap CDP message (over 8 MiB) is not held in memory: its first bytes identify the call it answers, that ONE call fails with `ErrReplyTooLarge` (a plain tool error: "the page's accessibility tree is too large to snapshot", "the screenshot is too large to return"), an over-cap event is dropped, and the connection lives on; only a message beyond 256 MiB (the discard bound) still drops the connection. The accessibility tree is requested with a depth bound, and the screenshot is captured as JPEG (a PNG of a noisy page could exceed the cap), then decoded, painted over and encoded again at the caps. The float-to-int conversion of the redaction rectangles is clamped (NaN and huge values).
- **`browser_wait`** recreates its isolated world when a navigation destroys the execution context and keeps polling to its timeout (a world that cannot be recreated yet is retried, not an error); URL mode matches the full URL from CDP, not the 500-character display copy.
- **The snapshot walk counts every level** for its recursion bound, skipped (ignored or unnamed generic) nodes included.
- **Runs of one workspace no longer share tabs.** Each run works in its own tab (the first run reuses the browser's own page, later runs open a new one inside the 3-tab pool); a `tab` argument may only name the run's own tab; `browser_tabs` lists only it; the console is per tab (each console line remembers its CDP session) and every result is labelled with the origin of the tab it actually came from. The workspace session is closed when the LAST live run using it ends. Notices (blocked requests and so on) are still session-wide: with two runs in one workspace one may see the other's notices (the proxy's refusals do not know the tab); accepted.
- **Timeline noise**: refusals (unknown tool, bad arguments, a limit) write at most 10 records a minute per run and then one "further refusals suppressed" line; calls that reached the browser are always recorded.
- **Password redaction, everything it does not cover** (beyond a field inside a shadow root or an iframe, already listed): a field a page switches to `type=text` before the scan, or whose text is hidden by CSS (`-webkit-text-security`) rather than `type=password`; an input inserted between the scan and the capture; `autocomplete=off` text inputs that hold secrets; textareas and contenteditable regions. More than 100 password inputs refuse the screenshot and the snapshot by design (a page cannot make the daemon cover only some).
- **The per-run capability token, and its residual, plainly.** The token that binds `browser.call` to a run lives in the `smind-browser` MCP child's environment and, for claude-native, in the private (0600) mcp-config file the CLI is started with, for the whole run. Another process of the same OS user can read a process environment on some systems (`/proc/<pid>/environ` on Linux, `ps eww`), so a same-user agent shell of run A could find run B's token and drive B's workspace browser session, crossing the per-workspace switch. This is the same limit as the daemon token and the validator and steward seat tokens: same-user processes are not isolated from each other by smind, and the browser gate stays dark. What the token does give: a bare run id (which `run.list` shows) is no longer enough, the token is minted only when the row is actually delivered (not for codex-native, a plugin provider, or a row the provider skipped; revoked then), and it is dropped when the run ends. Why it is not shorter-lived: the MCP stdio contract passes a child only argv, environment and the file the CLI reads; there is no inherited-descriptor or stdin handshake smind could use without a new protocol, and clearing the variable from the child's own environment does not change what `/proc` shows. A single-use attach exchange (the child trades the token for a per-connection credential at its first call) is the next step if the Human wants the window closed; it was not built (no bigger isolation scheme). **[Superseded by PR 3b-2: there is no websocket `browser.call`, no `session.identify` for the browser and no token; the child reaches the broker over its run's own socket, see "PR 3b-2: progress".]**

### PR 3b spec (written before coding, as decided)

**3b-1, proxy authentication.**
- At session start the daemon generates a random 128-bit secret (never logged, never in argv or the profile) and gives it to the proxy and to the session; the browser is not told it on its command line.
- The proxy answers any request or `CONNECT` without a valid `Proxy-Authorization: Basic base64("smind:<secret>")` with `407` and `Proxy-Authenticate: Basic realm="smind"`, compares in constant time, and counts failures (a flood of unauthenticated attempts is cut after a small number per minute and noted once).
- The browser answers the challenge through CDP: every attached target enables `Fetch` with `handleAuthRequests: true`; a `Fetch.authRequired` whose `authChallenge.source` is `Proxy` gets `Fetch.continueWithAuth` with the secret; a challenge from any other source (a website asking for credentials) is answered with `CancelAuth`, never with the secret. The credential is cached by the browser per proxy, so the challenge arrives once.
- Tests: proxy table (no header, wrong secret, wrong scheme, right secret; absolute-form and `CONNECT`; timing-safe compare; the 407 carries no hint of the secret), fake-CDP session test (proxy challenge answered with the secret, a server challenge cancelled, a challenge on a worker target), a real-Chrome smoke (the whole read-tools smoke runs through the authenticated proxy; a `curl`-style direct request to the proxy port without the secret gets 407), mutations (secret in the wrong source, compare weakened, 407 skipped for `CONNECT`).

**3b-2, a per-run socket with a peer-credential check.**
- The daemon listens on one local socket per browser run (a directory under the daemon home, mode `0700`, the socket `0600`, removed when the run ends). The `smind-browser` row's environment carries its path (`SMIND_BROWSER_SOCKET`); the token and the daemon websocket are no longer used by the child. The socket speaks only `browser.call` (a closed set of one method).
- **The check, on every accepted connection, before a byte is read:** (1) the peer's user id equals the daemon's; (2) the peer's process id is the run's own agent process or one of its descendants (the daemon spawned the agent and knows its pid; it walks the peer's parent chain); a process of another run, another user, or one outside the run's tree is closed at once. A same-user shell of run A therefore cannot call run B's socket, which is what the token could not stop.
- **Linux:** `SO_PEERCRED` gives uid and pid. **macOS:** `LOCAL_PEERCRED` gives the uid and `LOCAL_PEERPID` the pid (read with `getsockopt` on the accepted connection). The ancestry walk uses the parent pid from `/proc/<pid>/stat` (Linux) or `sysctl kern.proc.pid` (macOS). A pid is re-read after the walk to narrow reuse races; a process that exits mid-check is refused.
- **Windows (written down before coding):** unix-socket peer credentials do not exist the same way. The approach is a **named pipe** `\\\\.\\pipe\\smind-browser-<run id>`, created with a DACL that grants access to the daemon's user SID only (`D:(A;;GA;;;<sid>)`, no inheritance, `FILE_FLAG_FIRST_PIPE_INSTANCE` so nobody can squat the name) and checked on each connection: `GetNamedPipeClientProcessId` gives the client pid, `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` then `IsProcessInJob` against the run's **Job Object** (the agent CLI of a run already runs inside a kill-on-close job, see `internal/winjob`; the run's job handle is what the check is made against, so "in the run's job" is the Windows equivalent of "descendant of the run's agent"). Descendants of the agent are in its job unless they escape it (a breakaway); the job is created without `JOB_OBJECT_LIMIT_BREAKAWAY_OK`, so they cannot. This is **not verifiable on this macOS machine**: the Windows path is written, unit-tested against interfaces and compile-checked, and its first real run is the Windows CI job plus a manual run the Human must do; the PR body says so. If the job check proves unavailable for a provider whose agent is not job-contained, that provider gets no browser on Windows until it is (the row is simply not delivered), never a weaker check.
- The token is removed (the socket path plus the peer check replace it); `browser.call` over the daemon websocket stays refused for the child's identity (the handler is no longer reachable by an identified run connection at all).
- Tests: a table of peers (right user and in-tree, same user outside the tree, another run's tree, a different user where the test can create one, a closed or exiting peer), the permissions of the directory and socket, removal at run end, a stale socket from a crashed daemon swept at start, `browser.call` refused on the websocket; mutations (ancestry check skipped, uid check skipped, socket mode widened, the websocket path left open); the macOS path verified here, the Linux path through its build-tagged unit tests and CI, the Windows path as stated above.

**What 3b does not do:** it does not isolate same-user processes from the daemon itself (the daemon token on `/ws` is still readable by a same-user process; that is ADR-0056's open question), and it does not authenticate the browser's own page content. It closes the two residuals this lane named.

### PR 3b-1: progress, deviations and validation (proxy authentication)

Built as specified. `StartProxy` generates a 128-bit secret per session (`Proxy.Secret()`, never in argv, the profile, a notice or any `%v` of the proxy; the config copy is cleared). Every request and `CONNECT` is authenticated before its target is parsed: no header, a wrong scheme or user, a wrong or prefixed secret get `407` with `Proxy-Authenticate: Basic realm="smind"` and no other hint; the comparison is a constant-time compare of two SHA-256 sums (so the length of what a client sent leaks nothing). More than 20 WRONG credentials a minute cut that connection without an answer and note it once. A request with no credential at all is never cut and always gets the 407 (the browser's first request has none), so another local process cannot lock the browser out by spamming (found by both reviewers; the first draft cut any unauthenticated request). `Proxy-Authorization` is stripped on the forward path (it was already a hop-by-hop header) and a test pins that the upstream never sees it.

The session enables `Fetch` with `handleAuthRequests: true` on every target (pages, frames, workers). `Fetch.authRequired` is queued with `requestPaused` (same bounded pool and byte budget); a challenge answers `ProvideCredentials` ONLY when its source is `Proxy` AND its origin is exactly this session's proxy (`http://127.0.0.1:<port>`); anything else (a web site's challenge, a Server challenge that borrows the proxy origin, another proxy address, an https origin, an empty origin) is cancelled with no credential, and noted.

`browser.PrereqProxyAuth` is now `true`; `TestGateReadyRequiresBothPrerequisites` still blocks `GateReady` until `PrereqRunSocket` (3b-2).

The constant-time property is by construction (both sides are hashed, then `subtle.ConstantTimeCompare`), not by a timing test. A refused-challenge notice is once per session. **Accepted residuals (stated).** Before authentication a local process can still hold connection slots: the proxy has 64 slots and a 2 s header timeout (lowered from 10 s for this reason), so a process that keeps opening silent connections can starve the browser of slots for as long as it keeps doing so; it gains no access, and the session would simply stall until the process stops (same-uid processes are not isolated by smind, as stated for the daemon token). `Fetch.authRequired` events share the request queue (4096 events) and its byte budget with `requestPaused`, so a page can still raise a request flood that closes the session; a test pins that 300 Server challenges do not starve the proxy challenge. The exact-origin match (`u.Host == proxy.Addr()`) is covered in CI by the fake-CDP tests only; against a real Chrome it is covered by the opt-in smoke (`SMIND_BROWSER_SMOKE=1`), which is not run in CI.

Verified: proxy table tests (13 credentials x absolute-form and CONNECT), unauthenticated requests never reach the resolver or a dial, upstream never sees the secret, flood cut and noted once, secret not printed, fake-CDP session tests (the proxy challenge answered, five kinds of other challenge cancelled, a worker target, the secret not in launch options), and the real-Chrome smokes (the read-tools smoke runs entirely through the authenticated proxy; a direct request to the proxy port without the secret gets a bare `407`). NOT verified: Windows and Linux Chrome (macOS only); that every Chrome version raises `Fetch.authRequired` for a CONNECT 407 (measured on the installed Chrome only).
### PR 3b-2: progress, deviations and validation (the per-run socket)

Built per the 3b-2 spec (`browser-for-agents-pr3b2.md`, merged separately). `internal/browser/runsock`: `PeerReader` (Linux `SO_PEERCRED`; macOS `LOCAL_PEERCRED` and `LOCAL_PEERPID`), `ProcTree` and `InTree` (Linux `/proc/<pid>/stat`, macOS `kern.proc.pid`, Windows toolhelp), the `Hub` (one socket per run, directory `0700` verified, socket `0600`, a 100-byte path rule with a `/tmp/smind-<uid>` fallback, stale sockets swept at start, closed at run end), the one-tool protocol (16 KiB request lines, strict fields, deadlines) and `checkCred`, the one decision every platform makes. The GLM peers wrote the interface-bounded helpers (peer credentials, process tree) from step-by-step briefs; the hub, protocol, wiring, child, Windows code and tests are mine.

- **The check, on every accepted connection, before a byte is read:** the peer's uid is the daemon's, and the peer's pid is the run's root agent process or a descendant (parent-chain walk, depth cap 64, loop guard, reparent-to-init refused), with the root's start time unchanged (re-read after the walk, as is the peer's). Refusals close the connection with no reply and leave a fixed-text record (no pid).

- `browser.PrereqRunSocket` is now `true`; `GateReady` is still `false` (PR 4), and `TestGateReadyRequiresBothPrerequisites` still passes.

**Deviation 1, important: the Claude CLI path gets NO browser row.** The socket is bound to the agent's process id, which the daemon knows only for ACP agents (`acp.Client.PID()`; the daemon starts the agent before it builds the MCP rows). The Claude CLI is started by `claude-agent-sdk-go` (v0.4.2) after the rows are built and the SDK does not expose its process id, so `mcpRowsFor` passes 0 and delivers no browser row. **Deviation 2, decided stricter (Steward 5 review): the browser is NOT offered on Windows.** The spec wanted Job Object membership; the run's job handle is not plumbed to this package, and the parent-chain walk that replaced it is spoofable on Windows: a same-user outsider can create a process with `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS` naming the run's agent as its parent (it needs `PROCESS_CREATE_PROCESS` on that process), so its parent pid says "descendant". So `NewSystemHub` on Windows returns `ErrWindowsUnsupported` (the unexported `windowsHubEnabled` switch is false): no socket, no browser row on Windows. The pipe code (protected one-SID DACL, first-instance flag, remote clients rejected) stays compile-checked (`GOOS=windows go vet`) and unwired. **None of it has ever been run on Windows**, and no CI job runs this package there (the Windows CI job builds and tests only `internal/terminal`); a manual Windows run is the only verification there will be, and it is moot while the switch is off. **To do before the browser is offered on Windows:** plumb the run's Job Object handle to the hub and check `IsProcessInJob(client process, run job)` (the job is created without `JOB_OBJECT_LIMIT_BREAKAWAY_OK`), add a test, then flip the switch and run it on a Windows machine; the pipe's same-user instance squatting (the child does not authenticate the server end; `GetNamedPipeServerProcessId`) must be addressed in the same change.

**Linux** code is compile-checked here and its `/proc` parser is unit-tested with fixtures on every platform; the live peer-credential and ancestry paths run only where someone runs the tests on Linux (the main CI job does run `go test ./...` on Linux).

Review round fixes (two fresh-context sub-agents): refusals are counted per run and the first is logged (`Hub.Refusals`), the default fallback directory is keyed on the daemon's own socket directory (two daemons of one user no longer sweep each other's sockets), a handler panic is an error reply and not a daemon crash, a transient `Accept` failure backs off instead of ending the loop, a re-`Open` closes the old socket outside the hub lock, `InTree` refuses a parent that started after its child (a recycled pid; matters on Windows, which never reparents), and the Windows pipe close cancels pending I/O and no longer holds a lock while closing.

Named-test notes: `TestServerRefusesAnotherUID` and `TestServerRefusesAReusedRoot` are rows of `TestServerCheckTable` (and the root-start rows of `TestInTreeTable`); `TestCallRunHonoursTheGates` is `TestBrowserCall_DaemonRechecksTheGateOnEveryCall` plus the kill-switch tests; `TestNoRowWithoutARootPid`, `TestRowEnvHasNoSecret` and `TestBrowserPolicyHasNoToken` live in `taskrunner` (`TestBrowserSocketIsOpenedOnlyWhereTheRowIsDelivered`, the row-env test) and `runs` (`TestBrowserPolicy_RowOnlyWhenAllGatesHold`); `TestWindowsPeerCheckUsesTheJobOracle` does not exist because the Job Object oracle was not built (deviation 2); there is no `SMIND_BROWSER_SMOKE` run of 3b-2 (the real helper process trees in `hub_unix_test.go` and `TestBrowserMCP_ThroughARealHub` are the real-credential coverage).

More stated residuals: the peer is checked when it connects, not per request, so a connected descriptor handed by an in-tree process to an outsider (`SCM_RIGHTS`, inheritance, or `pidfd_getfd` where ptrace is open) is delegation by that in-tree process; the macOS `LOCAL_PEERPID` semantics for a descriptor passed this way were not tested; a handler is cancelled at run end, not when its connection drops, so an in-tree process can hold the run's 8 connection slots (it is the run's own principal); the agent's pid is read after `Initialize`, not at spawn (a very small reuse window); on Windows the parent-chain walk makes the browser unavailable to a process whose launcher exited (fail closed), each connection costs several process snapshots, and a same-user process can add a pipe instance of the same name (the unix rebinding limit); none of the Windows code has been run.

Disclosures after the Steward review (stated, not fixed): **every ACP provider reads `client.PID()` after `Initialize`**, so a provider whose launcher execs or double-forks away from the process the daemon started, an agent that routes its MCP children through a server outside its own tree, ACP terminals the daemon spawns on the agent's behalf (not descendants), and an agent in its own PID namespace or sandbox lose the browser: the row is advertised and the child fails at call time, now with "the browser is not available for this agent: the daemon cannot verify the caller" (an unknown pid builds no row). The Claude CLI path has no browser until the SDK reports its pid (deviation 1; a product gap for the Human before PR 4). Unix residuals: the dead-peer pid-reuse window (Linux 6.5+ `SO_PEERPIDFD` would close it and is not used; macOS has no equivalent), a same-uid `ptrace`/`pidfd_getfd` takeover of an in-tree process (the same class as fd delegation), the socket is created under the process umask and then `chmod 0600` (the verified `0700` directory covers the window), and an existing socket directory that is not exactly `0700` and ours is REFUSED (logged as "the socket directory was refused, so no run gets the browser", not repaired). Fixed after the review: the peer check comes before connection-slot accounting (a bounded pending-check pool, 32, so an unauthenticated flood cannot starve the real child), the sweep removes only sockets that refuse a connect (a second daemon cannot break a live one), closing a run's socket waits at most 3 s for a handler that ignores its context, the child bounds a reply (32 MiB) and a call (the caller's deadline, else 2 min), and a system hub is lazy (it creates or sweeps nothing until the first Open, so tests never touch a real home).

Residuals stated: processes inside a run's own tree (the run's agent and its shells) can use that run's browser (they are the run's principal); a descendant that detaches and reparents falls outside the tree and is refused; a process that can write the daemon-user's files or ptrace the agent is out of scope (same-user, ADR-0056).
