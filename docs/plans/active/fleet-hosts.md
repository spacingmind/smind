## Acceptance Criteria

Identity, registry, link, pairing (F1)
- AC1 With `fleet.enabled` false (default) or absent: no `host-key` is created, no `fleet.*` method is served or answered (method-not-found), no table is touched, `smind --help` still lists `host` but every `smind host` subcommand says fleet is off; a golden test over the existing wsapi method map shows no other change.
- AC2 The host key is created lazily on first enable with mode 0600 through `internal/securefile`; `hostId = base32(SHA-256(pub))[:26]` equals the D35 derivation (shared vector); an unreadable/corrupt key file refuses to start fleet (never regenerates silently).
- AC3 `smind host invite` opens a pairing window with the `devices.Window` rules (default 10 min, 1 slot, only a peer first seen at/after `OpenedAt` takes it) and prints an invite whose payload is in the URL fragment only; the invite contains no daemon password and no provider secret.
- AC4 `smind host add <invite>` pins the invite's public key, runs `fleet.hello` mutually (both signatures verified), and shows the same 6-digit SAS on both hosts; the responder records the initiator as `pending` and only a human `approve` makes the inbound record `approved`.
- AC5 **Symmetric model (D1):** one pairing creates exactly two directed links. After pairing, initiator→responder is enabled (responder holds the default forward grant), responder→initiator is **disabled** (initiator holds no inbound record that allows it). A call over the disabled direction is refused `not_granted` on the callee.
- AC6 `smind host enable-reverse <peer>` (run on the receiving host, local-only) creates the inbound record with the **default reverse grant (read-only, 0 live agents, 0 wall, $0)** and the peer's outbound record becomes usable only after the callee's `fleet.link.state` notice; `disable-reverse` closes the live connection immediately. A mesh is enable-reverse on every pair; no mesh object exists (a test walks the schema).
- AC7 Host hello is mutual and pinned: a callee presenting another key is refused by the caller with `peer_identity_changed`, never accepted silently; a caller key not approved is refused with `awaiting_approval`/`revoked`; the fresh challenge makes a recorded hello transcript useless on a new connection (replay test).
- AC8 Direct links refuse a cleartext `ws://` route to a non-loopback address outside the Tailscale ranges unless `--allow-cleartext`; relay links use E2EE v2 and fail closed on a fingerprint mismatch; both transports end in the same hello.
- AC9 A host principal can call only `fleet.*`: every other method in the wsapi handler map is refused `forbidden` for it (handler-map walk), `fleet.host.*` admin methods are local-only and in neither `RunScopedMethods` nor the plugin allowlist, and no fleet method can write a grant, link, policy or secret (type-level: the fleet param structs have no such fields; test by reflection).
- AC10 `smind host ls --json` never prints a key, secret, relay host secret or password; `fleet-secrets` is 0600 and the relay secret is redacted in logs (canary test).
- AC11 Web Settings → Hosts lists hosts with state, direction toggles, grant editor, invite/add/approve with the SAS, light+dark at 1280 and 390; the inbox shows `host_pair` / `host_down` / `host_refused` rows (S9); mobile lists hosts and approves a pending one from the inbox row (no mobile pairing).

Remote read (F2)
- AC12 `fleet.info`, `fleet.workspace.list`, `fleet.task.list|get`, `fleet.run.status`, `fleet.task.activity` work for a granted peer, return only owner-host data, never local paths, never credential-bearing URLs, assistant text ≤ 1 KiB per event, cursor-paged, and honour `workspaces.read`.
- AC13 **Provenance (D3):** every request carries `fleet.prov`; the callee verifies in order principal match, not-in-chain (cycle), `len(hops)==1` (hop limit), replay/staleness, grant + budget; each failure is a typed `fleet_refused{code}` with an audit row on the callee and on the caller.
- AC14 Audit on both ends: one `fleet_audit` row per call with `{direction, host, trace, reqId, method, outcome, code, latencyMs, bytes, summary}`; `summary` has no prompt body (SHA-256 + ≤ 120 redacted chars); 30-day retention; `smind host audit` and the Hosts page read it.
- AC15 CLI `smind host workspaces <host>` and `smind host tasks <host>`; MCP `list_hosts` and the read tools accept `host`; omitted host = local, byte-identical to today's results.
- AC16 **Version/caps (D7):** on every reconnect each side requires equal `fleetV` major and `caps` ⊇ required; a mismatch yields `fleet_version_unsupported{needs, has, host, guidance}` and the link stays `refused` (no downgrade, no local fallback, local operations unaffected); a daemon with no `fleet.*` (method-not-found) maps to the same guidance.

Remote create, send, finish (F3)
- AC17 `fleet.task.create` requires `create` and a workspace in `workspaces.write`; provider and model are **required**; the request type has no `permissionMode`, `profileId`, `env`, `cwd`, `attachments` or `mcp` field; a provider the callee lacks fails `provider_not_configured`; the branch is fetched from the callee's own origin (`branch_not_found` otherwise); no path, diff or file upload exists.
- AC18 `fleet.task.send` and `fleet.task.stop` act only on tasks this peer created (`not_owner` otherwise); prompts are text-only; `idempotencyKey` (24 h) makes an ambiguous retry return the same task/run; a different key creates another.
- AC19 Remote-created tasks have `source=remote`, `origin_host`, `origin_trace`; they run under the callee's own mode ceiling and the ADR-0047 floor in every mode; their permission requests go to the **callee's** inbox with a host chip, the caller sees only `waiting_permission` and cannot answer (no fleet method can).
- AC20 **Per-origin budget (D3):** the callee refuses with `budget_exceeded{which}` when remote-origin live agents ≥ `maxLiveAgents` or reported 24 h cost ≥ `maxCostUSD`, counted per origin host across all trace ids; a run over `maxWallSeconds` is stopped by the callee and reported `wall_limit`; nil cost is never estimated.
- AC21 **Durable finish notification (D4):** the caller writes the `fleet_watches` row and the mirror in one local commit; at restart it resumes with the cursor; a run that finished during the downtime is delivered once through the ADR-0041 B3 queue with `host=<alias>` and the remote text marked untrusted and ≤ 1 KiB; three consecutive failed observations (capped backoff, "connecting" attempts do not count) deliver "status unknown", never "finished"; a confirmed removed host delivers "host unavailable" at once; a definitely-unsent prompt creates no watch; a failed local write reports failure and the create is retry-safe.
- AC22 MCP `task_new/task_send/task_status/task_logs/task_stop/workspace_list` accept `host`; results carry `host` and `globalId` (`alias:id`); a Peer seat and a remote-origin task get no fleet tools and a fleet call from them is refused locally with `hop_limit`.

Tree across hosts, UI (F4)
- AC23 `task.tree` shows remote children under their local parent with a `remote` flag, host alias and mirrored state; usage and live-count rollups include remote reported cost and count; ADR-0041 A5's tree budget at admission counts remote spend; mirror rows are cache only (deleting them loses nothing; every mutation goes to the owner).
- AC24 Exactly one owner per task: a mutation on a mirror goes to the owner and a local mirror is never updated by anything but the owner's events; ids are `alias:id` in UI/CLI/MCP and `{hostId, id}` on the wire; an alias rename changes no stored wire id.
- AC25 Web shows a host label chip on remote nodes in tree, inbox and task header (light+dark, 1280/390, transition frames of the tree reviewed); mobile shows the chip.

Capability routing (F5)
- AC26 Hosts carry operator-set labels (`os:windows`, `arch:arm64`, `gpu:cuda`, free `k:v`, ≤ 16, validated); `host` in MCP/CLI may be `labels:{...}`; the selector must resolve to exactly one enabled, connected host unless `any:true` (then least live remote agents, ties by alias); zero matches or ambiguity are model-readable errors; there is no automatic retry on another host.

### F1b design (2026-10-31, Lead)

Wire (all JSON over the existing wsapi envelope; a host is "a normal client" that then identifies itself, like `session.identify`, so it can only lose powers):

- `fleet.challenge` (any admitted conn, fleet on) -> `{nonceC, hostId, fleetV, caps, version}`; the nonce is single-use per connection.
- `fleet.hello {v:1, hostId, pub, nonceA, ts, version, fleetV, caps, sig}`, `sig = Ed25519("smind-fleet-hello-v1" || calleeId || callerId || nonceC || nonceA || ts)`; reply `fleet.hello.ok {hostId, pub, sig, state, version, fleetV, caps}` (`sig` over the same fields under domain `smind-fleet-hello-ok-v1`, so a callee signature cannot be replayed as a caller one). Success makes the conn a host principal: only `hostAllowed` (`fleet.pair.request`, `fleet.link.state`, `fleet.info` later) is served, everything else `forbidden`. `ts` must be within +-120 s. Refusal codes: `unknown_host`, `awaiting_approval`, `revoked`, `not_granted` (inbound link off), `bad_signature`, `stale`, `replay` (nonce reuse), `fleet_version_unsupported {needs,has,host,guidance}`; the caller adds `peer_identity_changed` (callee pub != pinned).
- Channel binding to the E2EE transcript is NOT in F1b (the bridge transport does not expose it to wsapi); the hello is bound to a fresh per-connection `nonceC`, which is what makes a recorded transcript useless (AC7). Stated as not done in the PR.
- `fleet.pair.request {alias, label}` on a conn whose hello came from an unknown host while the pairing window is open (the slot is taken here, one slot, only a host first seen after `OpenedAt`): records the caller `pending` (`registry.AcceptPairRequest`), returns `{state:"pending", sas}`. SAS = 6 digits of SHA-256("smind-fleet-sas-v1" || callerPub || calleePub || nonceC || nonceA), identical on both hosts.
- `fleet.link.state {state}` from an approved host principal: `reverse_enabled` / `reverse_disabled` (peer says it now grants / stops granting us) -> callee flips its OUTBOUND record (`SetOutboundEnabled`). A notice never carries a grant.
- Admin (local-only: `rc.local`, not run-scoped, not plugin, not host-allowed): `fleet.host.list|invite|add|approve|reject|rename|rm|grant|enable_reverse|disable_reverse|test`. `fleet.host.get` and `audit` are not in F1b (audit writer is F2a).
- Transport JSON on the outbound link: `{"kind":"direct","url":"wss://h:p","fingerprint":"","allowCleartext":false}` or `{"kind":"relay", ...}`. Secrets (daemon password, relay secret) live only in `$SMIND_HOME/fleet-secrets` (0600 JSON keyed by hostId), never in the registry, the invite or any API.
- Direct route rule (S4): `ws://` to a non-loopback address outside `100.64.0.0/10` / `fd7a:115c:a1e0::/48` is refused unless `allowCleartext`; `wss` and loopback pass.
- Relay: the caller opens a relay data route as a device with the host key as device key (the device id derivation is the host id), E2EE v2 with the callee's pinned X25519 key (fail closed on mismatch), then the same fleet hello. The callee's `smind host invite --via relay` opens the relay hub's pairing window (1 slot) so the first new device is admitted at relay level; the host is still `pending` at fleet level until a human approves. `host rm` / `disable-reverse` also revoke the relay device.
- Reverse: `smind host enable-reverse <peer>` runs on the RECEIVING host: `registry.EnableReverse`, then a `fleet.link.state{reverse_enabled}` over the live outbound link; `disable-reverse` closes the peer's inbound connection and notifies.

### F2a design (2026-10-31, Lead)

Callee read path. Package `internal/fleet/wire` (new, tiny: the Go types of the read methods, shared with F2b's caller client so the two cannot drift) and `internal/fleet/serve` (all callee logic, no wsapi import). `internal/wsapi/fleet_read.go` is a thin adapter: it registers the six methods, allows them for an `approved` host principal only (`fleetHostAllowed`), and calls `serve.Server.Handle(ctx, principalHostID, method, rawParams)`. `FleetOptions` gains `Store` and `Workspaces`; when `Store` is nil the read methods are not registered (fleet.link keeps working, existing tests unchanged).

Every read request is `{prov: {origin, trace, hops, originTask?, reqId, ts}, ...method params}` (ts is unix seconds). `Handle` runs, in this order and before any data access: principal match (`origin` == the authenticated link principal and, when present, `hops[0]` too; else `principal_mismatch`), cycle (this host is `origin` or in `hops`: `cycle`), hop limit (`len(hops) == 1`: `hop_limit`; an empty chain is refused too), staleness (`|now-ts| <= 120 s`: `stale`), replay (`reqId` already seen from this principal in the last 10 min: `replay`; the cache is per daemon process, bounded, and a restart only re-opens the 120 s window), grant (`registry.Authorize(principal, read, workspaceId)`: `not_granted`, never says why), per-origin read rate limit (token bucket, 20 req/s, burst 40: `rate_limited`). The refusal code is the wire error `code`. Every call, served or refused, writes one `fleet_audit` row (direction `in`, host = principal, trace, reqId, method, outcome `ok|refused|error`, code, latencyMs, response bytes, summary = `sha256=<hex> ` + at most 120 characters of the params without `prov` passed through `internal/learning/redact`). A sweeper deletes rows older than `store.FleetAuditRetention` at start and hourly (like the policy audit sweeper).

Result shapes are closed structs with no path, env, token, account or URL-with-credentials field (`wire.Workspace{id,title,repoUrl,defaultBranch}`, `wire.Task{id,workspaceId,title,branch,state,parentId,createdAt,updatedAt,origin{host,trace}}`, `wire.RunStatus{runId,taskId,state,provider,model,startedAt,finishedAt,stopReason,failureKind,costUsd}` (`costUsd` nil when unreported, never estimated), `wire.Activity{events,nextCursor,hasMore}` with `Event{seq,ts,type,text,truncated,toolName,toolStatus,stopReason}`: text is redacted and capped at 1 KiB, tool inputs and results never leave the host). `repoUrl` has userinfo stripped. `fleet.task.list` is cursor-paged (`cursor` = last task id, default 50, max 200) and filters to the grant's readable workspaces; `fleet.task.activity` pages by run event `seq` (default 50, max 200). Archived and system tasks are not listed.

Not in F2a (stated): the caller client, CLI and MCP (F2b); `fleet.read` as a separate advertised cap (the link cap is enough until a grant can lack read); `alias` in `fleet.info` (the callee has no name for itself, the caller names it); `waiting_permission` in run status (F3a, it needs the permission registry); budgets other than the read rate limit (F3a).

Peer plan F2a (peer-glm, disjoint scopes): S0 `internal/fleet/wire`; then S1 `internal/fleet/serve` provenance + replay + rate + audit (`prov.go`, `audit.go`) and S2 `internal/fleet/serve` read handlers (`read.go`, `redact.go`) in parallel; S3 `internal/wsapi/fleet_read.go` + store page query + daemon wiring + tests; S4 e2e and docs.

### F3a design (2026-10-31, Lead)

Callee write path. Same layering as F2a: `internal/fleet/wire` gains the write types, `internal/fleet/serve` all callee logic (no wsapi import), `internal/wsapi/fleet_write.go` a thin adapter implementing the effects.

- Wire (`wire/write.go`): `fleet.task.create {prov, idempotencyKey, workspaceId, provider, model, title, prompt, branch?, baseRef?}` -> `{taskId, runId, branch, replayed}`; `fleet.task.send {prov, taskId, idempotencyKey, prompt}` -> `{taskId, runId, replayed}`; `fleet.task.stop {prov, taskId, runId?}` -> `{stopped}`; `fleet.run.wait {prov, runId, cursor?, timeoutSeconds?}` -> `{runId, state, waitingPermission, events, nextCursor, done}`. The "stream" of `fleet.run.wait` is a bounded long poll (<= 25 s) resumed by `cursor` (run event seq): one wsapi connection, no server push, the caller loops; this keeps the principal model of F1b unchanged (stated deviation). `RunStatus` gains `waitingPermission`. New refusal codes: `budget_exceeded` (message names `which`: `live_agents|cost|wall`), `provider_not_configured`, `branch_not_found`, `not_owner`. The create type has no `permissionMode`, `profileId`, `env`, `cwd`, `attachments`, `mcp`, grant or secret field (reflection tests). Provider and model are required.
- Order inside `Server.Handle` (unchanged for reads): rate, provenance, then the method: decode, `Authorize(principal, op, workspaceId)` (create/send/stop need the op AND the workspace in `workspacesWrite`; for send/stop the workspace is the task's), ownership (`tasks.origin_host == principal`, else `not_owner`; absent task `not_found`), idempotency lookup, budget, effect, idempotency store. One mutex serialises budget check + start so two concurrent creates cannot both pass `maxLiveAgents`.
- Code arrives by git only (D5): the callee runs `git fetch origin <branch>` (or the baseRef) in the workspace repo, then `workspace.CreateTask` with `WithExistingBranch` / `WithBaseRef("origin/<ref>")`; a missing remote branch is `branch_not_found`. Names are validated (`git check-ref-format --branch`, no leading `-`, passed after `--`). No file, diff or path argument exists.
- Accounts and secrets (D6): the callee resolves `provider` against ITS registry (`provider_not_configured` when absent or disabled) and the run uses its own accounts and env; nothing of the caller's travels, because the type cannot carry it. `TestFleetSecretNeverLeavesHost` seeds a sentinel in the caller process env/config and greps every callee-side row, event, argv and log.
- Remote runs (`runs`): a new run source `remote` (`store.ChatQueueSourceRemote`, only the fleet adapter passes it; `run.start` still rejects it). In `StartWhenBusy` a remote source forces `AutoAccept=false` and inherits the existing non-human refusal of auto-approving modes (the grant's `permissionMode` is `""|default`, so the ceiling is the provider's asking default); in the permission decider a remote run skips the AutoAccept shortcut, so the ADR-0047 floor and the standing rules see every request in every mode; a request that is not decided by policy goes to the callee's inbox as today. `tasks.origin_host/origin_trace` and `runs.origin_host` are set on create/send. `waiting_permission` is read from `PendingPermissions()`. No fleet method answers a permission.
- Budget (`serve/budget.go`), per ORIGIN HOST across every trace id: live remote-origin runs `>= maxLiveAgents` -> `budget_exceeded{live_agents}`; reported cost of that origin's runs started in the last 24 h `>= maxCostUsd` -> `{cost}` (nil cost counts nothing, never estimated); `maxWallSeconds == 0` -> `{wall}`. Zero means zero (the reverse grant has no write op anyway). A send that starts a run counts as one more live agent.
- Wall limit (S17, `serve/wall.go`): a sweeper (default every 10 s, started like the audit sweeper) lists live remote-origin runs, compares `now - startedAt` with the principal's grant `maxWallSeconds`, stops the run and then stamps `runs.stop_reason = wall_limit`; it survives a daemon restart because it reads the store, not timers.
- Idempotency (`fleet_idem`, 24 h): lookup by `(principal, key)` first; the stored `response` is returned with `replayed:true`; a key reused for another method is `invalid_params`; the row is written after the effect (a crash between the two re-executes once: documented at-least-once for that window, the caller's watch row is the guard). A different key creates another task. Additive store query `GetFleetIdem`.
- Audit: every write call writes the same `fleet_audit` row as a read (prompt body never stored: hash + 120 redacted chars) with `taskId`/`runId`.
- Not in F3a (stated): the caller (F3b), the MCP write tools, a push stream for `fleet.run.wait`, attachments, a permission answer path, cost caps on running runs.

### F4 design (2026-10-31, Lead)

The tree across hosts. The mirror (`fleet_remote_tasks`, written by F3b in one commit with the watch) is the only local trace of a remote task: `local_task_id` is the LOCAL parent (the Lead that delegated), `host_id` + `remote_task_id` are the owner's wire identity, `state`/`cost_usd` are cache. Three moving parts.

- **Tree read model.** `tasktree.Build` gains a sibling `BuildWithRemote(tasks, facts, usage, remotes, root)` (`Build` calls it with nil, so every local caller is unchanged). A `RemoteTask{HostID, Alias, RemoteTaskID, ParentID, Title, State, CostUSD}` becomes a leaf node directly under its local parent, after the local children (ordered by host alias, then numeric remote id). Wire: nodes gain `host` (alias, omitted for local), `hostId`, `remote` (bool), `globalId` (`alias:id`, omitted for local); `Node.ID` of a remote node is NEGATIVE and only unique inside one response (`-1`, `-2`, ... in emission order), so every `int64` consumer that looks a node up by id (stall annotate, budget annotate, archive and stop-tree selection) can never hit a real task; the stable key for a client is `globalId`. A remote node has `tier` null, `childCount` 0, `run.state` mapped from the mirror (`running|waiting_permission|done|error|stopped`, anything else `idle`), `usage.own = {runs: 1, costUsd: mirror cost or null}`; its cost and its state roll into every ancestor's `usage.subtree` and `counts` exactly like a local leaf (nil stays nil, never estimated). Only the `task.tree` handler passes remotes (and only with fleet enabled); `buildTaskTree` (shared with `task.archiveFinished` and `task.stopTree`) does not, so no bulk action can ever name a mirror. A remote whose local parent is archived or missing is not shown (the mirror is not an orphan root).
- **Budget at admission (ADR-0041 A5).** `store.TreeKnownCost(rootID)` adds the reported cost of every mirror whose `local_task_id` is in the tree (nil cost adds nothing; a terminal mirror with nil cost counts as one unknown run). `runs.checkBudget` and `task.tree`'s budget annotation both call it, so admission and display agree; the `internal/runs` change is none beyond that (the hook already delegates to the store). Fleet off: the table is empty, results are identical. The per-tree concurrency guard does NOT count remote runs in F4 (the callee's per-origin `maxLiveAgents` is the bound); stated not done.
- **Mirror refresher (owner-only updates).** `internal/fleet/mirror`: `GlobalID(alias, id)` / `ParseGlobalID`, and a `Refresher` that every interval (default 10 s, one pass at start) lists mirrors in a non-terminal state and asks the OWNER (`client.RunStatus` by host id and remote task id, over the authenticated link) for the latest run; on success it upserts `state` and `cost_usd` of that one row through `PutFleetRemoteTaskAndWatch(t, nil)`. Errors (down link, refusal, not found) leave the row untouched (a stale cache, never a guess); the host id comes from the row, never from a response, so a peer can only change rows of its own host id. Terminal states stop being refreshed. Nothing else writes a mirror's state. Mutations on a remote task go through `remote.write` (`create|send|stop|wait`, F3b) which already takes `host` and the owner's task id: there is no local method that accepts a mirror (negative ids are unknown tasks).
- **Ids.** Wire `{hostId, id}` (node `hostId` + the task id inside `globalId` after the first colon); UI/CLI/MCP `alias:id`; the alias is resolved from `fleet_hosts` at read time, so a rename changes `host`/`globalId` text and nothing stored (`TestAliasRenameKeepsWireIds`). `TestOwnerHostIsSingle`: one `(host_id, remote_task_id)` row per remote task, the same remote id on two hosts is two nodes, and a local task id never resolves through a host.
- **UI.** One shared chip: the existing `Badge` (web) with the alias text, shown on remote nodes in the task tree (`task-lineage`), the inbox rows that carry a remote task or a host (`links.hostId` already exists) and the task header when the open task is a remote mirror (read-only header: no stop/archive/budget controls, "owned by <alias>" text). Mobile: the same text chip in `TaskTreeRow` and where a tree/inbox/task header already exists, no new screen.

Peer plan F4 (peer-glm, <= 2 in parallel, disjoint): S1 `internal/tasktree` + tests; S3 `internal/fleet/mirror` + tests (parallel); S2 store `TreeKnownCost` + `internal/wsapi/task_tree.go` handler merge + tests; S4 daemon wiring of the refresher after F3b merged; S5 web chip (peer-sonnet, screenshots); S6 mobile chip; S7 frames, docs.

### F5 design (2026-10-31, Lead)

Labels are local operator config on the CALLER's `fleet_hosts` row (new column `labels TEXT NOT NULL DEFAULT ''`, a JSON object; the migration `fleet_host_labels` lives in this PR only). They are never sent to the peer (the wire params and `fleet.info` do not carry them) and never leave the host except as a name in a selector error. Validation (`registry.ValidateLabels`): at most 16 pairs; key `^[a-z][a-z0-9._-]{0,31}$` and not containing `secret`, `token`, `passw`, `apikey`, `credential`; value `^[a-z0-9][a-z0-9._+-]{0,31}$`.

Selector (`internal/fleet/selector`, pure): `Select(sel, candidates)` over `Candidate{Alias, HostID, Labels, Enabled, Connected, Live}`. A host that is disabled (outbound link off), not approved or not connected never matches. Exactly one match resolves; zero matches (`selector_no_match`) and several matches without `any` (`selector_ambiguous`) are errors whose text lists the candidate aliases; with `any:true` the least `Live` wins, ties by alias. An empty label set is refused (a selector must name at least one label). There is no retry on another host.

Wire: one new local-only bridge method `remote.select {labels, any}` -> `{host, hostId}` (same guards as `remote.read`: local connection, hop limit); the MCP `host` argument (any JSON type in the schema, documented as alias string OR `{labels:{...}, any:true}`) and the CLI `--labels k:v,k:v [--any]` resolve through it to an alias first, then continue on the existing alias path. `Live` = the host's mirrored remote tasks in a non-terminal state. Admin: `fleet.host.labels {host, set?, remove?}` (local-only) behind `smind host label set|rm|ls`.

Not in F5: a Hosts settings page labels editor (follow-up), any change to `internal/tasktree`, the mirror, web or mobile.
